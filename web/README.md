# 《绿神话》课堂游戏 · 网页版使用说明

建筑节能低碳导论课的角色扮演策略游戏：**1 组政府 + 3 家企业**，在双碳背景下模拟 12 个月的决策互动。本网页版将 PPT 授课流程、Excel 记分表与规则结算全部自动化——老师只需要点按钮。

---

## 一、快速开始

### 方式 A：双击即用（推荐，无需任何安装）

直接双击 `web/index.html`，浏览器打开后即进入**中控台**。

> 双击打开（`file://` 协议）时，中控台 / 舞台页 / 归档页 / 自检页全部可用；**仅"观战二维码"需要方式 B**（手机扫码要求电脑开着 http 服务）。

### 方式 B：本地 http 服务（需要学生手机观战时）

在 `web/` 目录启动一个静态服务（任选其一）：

```bash
# Python（课堂电脑一般自带）
cd web
python -m http.server 8000

# 或 Node
npx serve web
```

然后浏览器访问 `http://localhost:8000/index.html`。

## 二、五个页面（同一文件，地址栏切换）

| 地址 | 页面 | 用途 | 谁看 |
|---|---|---|---|
| `#/control` | **中控台** | 开局设置、录入选择、统一揭示、政策执行、掷骰、救助、撤销、导出 | 主持人（老师） |
| `#/stage` | **舞台页** | 大字号投影：当前事件、企业分值牌、财政条 | 教室投影幕 |
| `#/spectate?s=…` | **观战页** | 手机扫码看到的公开快照 | 学生手机 |
| `#/archive` | **归档页** | 复盘：月度记录表、全程日志、骰子记录、快照、终局结算 | 课后复盘 |
| `#/test` | **自检页** | 浏览器端 5 项规则断言 | 排障用 |

**中控 ↔ 舞台同步原理**：两个窗口打开同一地址（不同 hash），通过 `localStorage` 的 `storage` 事件实时同步，另有 800ms 轮询兜底。**要求同一浏览器**（Chrome 开两个窗口即可；不要一个 Chrome 一个 Edge）。

### 推荐课堂布局

1. 电脑浏览器开两个窗口：`#/control`（自己看）+ `#/stage`（投影给学生）；
2. 舞台窗口按 `F11` 全屏；
3. 需要学生手机观战时，点中控台"观战二维码"，投影二维码让学生扫。

## 三、课堂流程（主持人操作手册）

### 1. 开局

中控台 → 开局设置：

- **企业命名**：默认"企业 A/B/C"，建议让学生起真实感的公司名；
- **政府命名**：默认"政府"；
- **掷骰模式**：`自动`（电脑掷，最省事，推荐）或 `手动`（让学生丢真骰子后录入点数，更有课堂气氛）。

点"创建游戏"进入 1 月。

### 2. 每月的常规节奏

每个月在 events 数据里定义为若干**步骤**（企业决策 → 政府决策 → 掷骰 → 自动事件等，每月不同）：

1. **企业决策月**（1/2/3/5/7/8/12 月等）：给各组 2-3 分钟讨论 →各组报选项（A/B/C/D）→ 中控台点选暂存 → **全部组提交后点"统一揭示"** → 结算自动完成，舞台页同步刷新分值；
   - 揭示前舞台页只显示"已提交 ✅ / 讨论中"，**不显示选择内容**（防止跟风）；
2. **政府决策月**（4/9/11 月等）：显示政策列表与财政影响，注意**财政红线**——余额不足的选项自动置灰；政策需填写"决策理由"（课堂思辨环节）；
3. **掷骰月**：自动模式直接出结果；手动模式逐组录入点数；
4. **自动事件月**（10 月油价等）：按各企业资产自动判定，点"执行结算"即可。

### 3. 风险与救助（自动触发）

- **生态 ≤ 20**：额外扣 10 分并记入风险日志（每月边沿触发一次）；
- **经济首次 ≤ 20**：弹出**救助弹窗**——政府可选择救助（企业 +10 / 财政 -10，每企业限一次）或放弃；
- **政府财政红线**：任意时点不得 < 0，不足的支出选项直接禁用。

### 4. 11 月 · 零碳园区专项

流程较长的月份：企业申报 →（加装者选设备）→ 揭示结算 → 资格自动检查（屋顶光伏 + 双向充电桩 + 蓄电池 ≥ 2 项）→ 政府 4 档试点资金（+0/+10/+20/+40）→ 生态奖惩。

### 5. 12 月后 · 年终

- **颁奖**：3 个奖项录入（不改分值）；
- **年终结算页**：企业排名 + 政府三目标判定（总生态 ≥ 240 / 总经济 ≥ 320 / 财政 ≥ 0）。

## 四、数据安全

| 能力 | 说明 |
|---|---|
| **自动存档** | 每次操作即写入浏览器 `localStorage`（键 `greentales-save`），误关浏览器 / 断电后重开自动恢复 |
| **快照撤销** | 每次结算前自动生成快照（上限 30 个）；"撤销"回退一步，"快照列表"可回退到任意历史点 |
| **JSON 导出** | 中控台 → 导出 → 下载 `.json` 文件（换电脑 / 存档 / 交教研组） |
| **JSON 导入** | 中控台 → 导入 → 选择 `.json`（版本校验，不匹配拒读） |
| **日志核对** | 归档页"全程日志"记录每一条数值变动的来龙去脉；"月度记录表"与 Excel 记分表口径一致，可课后逐项核对 |

> 课堂结束后**建议导出一份 JSON**——清浏览器缓存会连同 `localStorage` 一起清掉。

## 五、观战二维码

中控台 → "观战二维码"：生成当前公开状态的二维码 + URL。

- **内容**：月份、各企业经济/生态/资产、已提交状态、（揭示后）选择结果、财政——**不含**未揭示的选择；
- **方式**：同一局域网内学生手机扫码直接打开；也可复制 URL 发群；
- **性质**：一次性快照——数据是生成二维码那一刻的；游戏推进后需重新生成让学生再扫；
- **要求**：手机与电脑在同一网段（连同一个 Wi-Fi / 热点），电脑用方式 B 启动 http 服务。

## 六、常见问题

**Q1 双击打开后舞台页不更新？**
确认中控与舞台在**同一个浏览器**的两个窗口。`file://` 下个别浏览器限制 storage 事件，轮询兜底 800ms 内也会同步。

**Q2 刷新后进度丢了？**
正常不会——进度在 `localStorage`。若清了缓存或用了隐私模式，从导出的 JSON 导入恢复。

**Q3 想重开一局？**
中控台 → 开局设置 → 重新创建（旧局建议先导出 JSON 留档）。

**Q4 点数录错了 / 选择录错了？**
结算前：直接改选；结算后："撤销"回退一步，或从"快照列表"回到更早的时点。

**Q5 手机扫码打不开？**
① 电脑与手机不在同一网络；② 电脑防火墙拦了 8000 端口（Windows 首次启动会弹防火墙授权，允许即可）；③ 换用方式 B 的完整 IP 地址重试。

**Q6 如何核对分值？**
归档页 → "月度记录"表（口径与 Excel 记录表一致）或"全程日志"逐条核对。

## 七、技术说明（开发者）

- **零依赖零构建**：原生 HTML/CSS/JS，无框架、无网络字体、无 CDN——完全离线可用；
- **模块**：`js/engine.js` 为纯逻辑核心（Node/浏览器双模式，`require` 与 `<script>` 均可加载），`js/events.js` 为 12 个月事件静态数据，`js/qr.js` 为自研 QR Code Model 2 生成器（Byte 模式、ECL M、v1-13、Reed-Solomon GF(256)）；
- **测试**：仓库根目录 `tests/`（Node 断言，不进交付物）：`node tests/engine.test.js`（33 项数值/流程断言）、`node tests/fullgame.test.js`（5 项剧本全流程）、`node tests/qr.test.js`（6 项生成器结构断言）；二维码另经 pyzbar / OpenCV 双解码器实测（v1-v13、中文、URL 共 12 组全部通过）；
- **浏览器自检**：`#/test` 页内嵌 5 项断言，排障时先看它。
